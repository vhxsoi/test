# 업무 관리·지식 위키 앱 개발 계획

업무 기록을 바탕으로 업무 목록과 히스토리를 자동 생성하고, 반복 업무의 알림을 관리하며, 업무 도메인 지식 위키 초안을 작성하는 앱을 개발한다.

현재는 샘플 데이터로 동작하는 웹 UI 프로토타입이 구현되어 있다. 서버 저장, 인증, 실제 반복 실행, AI 자동 생성 및 메일 연동은 구현 예정이다.

## 목표와 사용 흐름

개인 업무 관리부터 시작해 팀 단위 업무와 지식 공유로 확장한다. 사용자는 업무 메모를 입력하고, 앱이 제안한 업무와 위키 초안을 검토한 뒤 확정한다.

1. 업무 메모나 회의록을 입력한다.
2. 앱이 실행할 업무, 담당자, 기한을 추출해 업무 목록 초안을 만든다.
3. 사용자가 내용을 확인하고 업무를 등록한다. 불명확한 담당자와 기한은 미정으로 남긴다.
4. 업무 상태 변경과 완료 기록이 히스토리에 자동으로 쌓인다.
5. 반복 업무는 일정에 따라 다음 회차가 생성되고, 알림 매니저가 예정·지연 업무를 안내한다.
6. 업무 기록에서 용어, 절차, 의사결정과 해결 사례를 추출해 출처가 연결된 위키 초안을 만든다.

| 영역 | 주요 기능 | 완료 기준 |
| --- | --- | --- |
| 업무 목록 | 업무 생성·수정·완료, 상태·기한·태그 필터, 메모에서 업무 추출 | 추출 결과를 수정·승인할 수 있고 재처리 시 중복 등록을 방지한다. |
| 업무 히스토리 | 생성·수정·상태 변경·완료 이벤트 자동 기록, 일별 타임라인 | 변경 시각과 변경 전후 내용이 남으며 업무별 기록을 조회할 수 있다. |
| 반복 업무 | 매일·매주·매월 반복 규칙, 시간대, 일시 중지·재개 | 각 회차가 독립 업무로 생성되고 재시작 후에도 누락·중복을 방지한다. |

| 도메인 지식 위키 | 용어·절차·의사결정·해결 사례 초안 생성, 검색, 버전 기록 | 각 초안에 원본 업무·메모 링크가 있고 승인 후 게시한다. |

## 자동 생성 원칙

- 업무 히스토리는 실제 변경 이벤트로 기록한다. AI 요약은 원본 기록과 함께 제공한다.
- AI가 추출한 업무와 위키 내용은 초안으로 저장하고 사용자 승인 후 확정한다.
- 원문에 없는 사실은 확정하지 않으며, 정보 충돌이나 부족한 근거는 검토 대상으로 표시한다.
- 위키 갱신은 기존 문서를 덮어쓰지 않고 변경 제안과 버전을 남긴다.
- AI 처리 실패 시에도 수동 업무 관리가 가능하도록 하고 실패한 작업은 재시도할 수 있게 한다.

## 제안 기술 구성

초기에는 단일 웹 앱으로 구현하고, 예약 작업은 별도 워커가 처리하도록 한다. 구체적인 프레임워크와 AI 공급자는 구현 시작 시 확정한다.

| 구성 | 제안 | 역할 |
| --- | --- | --- |
| 웹 UI·API | TypeScript, Next.js | 업무 목록, 타임라인, 알림함, 위키 편집·검토 화면 |
| 데이터 저장 | PostgreSQL | 업무, 이벤트, 반복 규칙, 알림, 위키 버전 저장 |
| 예약 작업 | 주기적으로 실행되는 워커 | 반복 회차 생성, 알림 발송, AI 작업 처리·재시도 |
| AI 연동 | 공급자 교체가 가능한 서버 모듈 | 구조화된 업무 추출, 히스토리 요약, 위키 초안 생성 |
| 테스트 | 단위·DB 통합·브라우저 테스트 | 반복 일정 계산, 중복 방지, 주요 사용자 흐름 검증 |

모든 일정은 사용자의 시간대를 기준으로 계산하고 시각은 UTC로 저장한다. 외부 AI 키는 서버의 보안 설정으로 관리하며 클라이언트나 저장소에 포함하지 않는다. 외부 AI로 전송할 기록의 범위를 사용자가 확인할 수 있게 한다.

| 알림 | 대상 업무·회차, 예정 시각, 발송 상태, 읽음 여부, 재시도 횟수 |

반복 회차와 알림에는 중복 방지 키를 둔다. 업무 변경과 이벤트 기록은 하나의 트랜잭션으로 저장한다. 월말·윤년·시간대 변경 및 워커 중단 후 밀린 회차의 처리 정책은 반복 기능 구현 단계에서 명시하고 테스트한다.

- [ ] 앱 구조, 로컬 실행 환경, DB 마이그레이션, CI를 구성한다.
- [ ] 개인 사용자 인증과 데이터 접근 범위를 구현한다.
- [ ] 업무 생성·수정·완료 및 목록 필터 화면을 구현한다.

초기 사용을 통해 업무 추출 승인·수정 비율, 중복 회차·알림 발생 건수, 알림 지연, 위키 초안 승인율과 출처 연결률을 확인한다. 수치 목표는 실제 사용 기준선을 확보한 뒤 정한다.

구현 시작 시에는 주요 입력 경로, 개인·팀 사용 범위, 알림 채널, AI 공급자와 비용 한도를 확정한다. 별도 요구가 없으면 MVP는 개인 사용자, 직접 메모 입력, 앱 내 알림으로 시작한다.

## UI 프로토타입 실행

Node.js 20 이상에서 의존성을 설치한 뒤 실행한다.

```bash
cd /workspace/test
npm ci
npm start
```

기본 포트는 3000이며 `PORT` 환경 변수로 변경할 수 있다. `npm run check`로 JavaScript 구문을 검사한다.

대시보드, 업무 목록, 히스토리, 반복 업무, 위키, 알림함 화면을 제공한다. 새 업무 등록과 완료 처리, 검색·상태 필터, 반복 업무 활성 상태 변경, 위키 초안 게시 및 알림 읽음 처리를 사용할 수 있다. 데이터는 현재 브라우저의 localStorage에 저장되므로 다른 기기와 공유되지 않으며, 브라우저 데이터를 삭제하면 초기 샘플로 돌아간다.

반복 업무 활성 상태는 UI 설정만 저장한다. 예약 실행, 외부 알림 발송, 사용자 인증과 Gmail 연동은 연결되지 않았다. GPT 정리 마법사의 API 호출 코드는 구현되어 있으며 서버 API 키 설정이 필요하다. 위키는 예시 문서이며 업무 출처 연결은 구현 예정이다.

## Route node 배치 UI

첫 화면은 항로와 서무를 함께 배치하는 업무 노드 보드다. 가상의 항로 6개로 공동운항·판매·구매·교환, 동일 항로명의 별도 ID, 운영·종료 및 업데이트 예정 상태를 비교할 수 있다. 권역·계약 유형 필터와 항로명·ID·파트너 검색을 제공한다.

카드를 선택하면 Route node 상세와 내부 History node(`Update date`, `Cycle`, `업데이트 항목`, `Remark`)를 확인하고 비고를 브라우저에 저장할 수 있다. Contract node는 기밀 계약 내용을 저장하지 않고 관련 LLM notebook 링크를 참조하는 별도 노드이며, 현재 UI에는 연결 ID만 표시한다. Notebook 링크는 미설정이며 앱이나 마법사가 내용을 자동으로 읽거나 전송하지 않는다. 선사 코드는 별도 예시 사전과 연결되어 있다.

업데이트 주기는 매월·분기별·매년·선박 n척 기준 n주를 지원한다. Due date는 최근 History의 업데이트일에 한 주기를 더한 값이며, 선박 기준은 추정값으로 표시한다. 별도 기준일보다 실제 최근 업데이트일을 우선한다. 샘플 화면의 비교 기준일은 2026-10-13으로 고정되어 있으며 실제 운항·계약 데이터 및 알림 발송과 연결되지 않았다.

## GPT 정리 마법사

사이드바의 **GPT 정리 마법사**에서 원문을 붙여 넣고 내용 요약, Route node 정형화 또는 History node 정형화를 선택한다. 외부 전송을 확인한 뒤 실행하면 요약, 필드별 값과 원문 인용 근거, 누락·검토 항목을 보여준다. 원문에 없는 값은 미확인으로 남기며 선박 n척은 n주 추정으로 환산한다. 결과를 수정하고 검토한 후 JSON으로 내보낼 수 있다. 기존 노드나 DB를 자동 변경하지 않는다.

### Windows 실행과 API 설정

Node.js 20 이상이 필요하다. PowerShell에서 저장소 폴더로 이동하고 `npm ci`로 의존성을 설치한 뒤 아래 명령으로 API 키를 화면에 표시하지 않고 입력한다. 키는 서버 프로세스 환경에서만 사용하고 실행 종료 후 해당 PowerShell 환경에서 제거한다. 키를 채팅·코드·브라우저에 입력하지 않는다.

```powershell
$worknoteSecret = Read-Host "OpenAI API key" -AsSecureString
try {
    $env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new("", $worknoteSecret).Password
    npm start
} finally {
    Remove-Item Env:OPENAI_API_KEY -ErrorAction SilentlyContinue
    $worknoteSecret.Dispose()
}
```

기본 모델은 `gpt-4.1-mini`이며 `OPENAI_MODEL` 환경 변수로 Structured Outputs를 지원하는 모델을 선택할 수 있다. 브라우저에서 `http://127.0.0.1:3000`을 연다. API 키가 없어도 기존 UI는 사용할 수 있으며 GPT 실행은 오류 안내와 함께 중단된다. ChatGPT 구독과 OpenAI API 사용료는 별도이며 API 프로젝트의 사용량·예산 알림을 설정하는 것이 좋다.

### 보안과 현재 범위

- 서버는 `127.0.0.1`에만 바인딩한다. Host·Origin 확인, 앱 세션 토큰, 외부 출처 차단과 CSP를 적용한다. 이 토큰은 같은 PC의 악성 프로그램으로부터 보호하는 OS 인증을 대체하지 않는다.
- 선택한 원문과 정리 유형만 OpenAI Responses API로 전송한다. 전체 DB나 다른 노드, 로컬 파일을 자동 전송하지 않으며 AI 도구 실행도 사용하지 않는다.
- 원문·API 키·응답을 파일이나 서버 로그에 남기지 않는다. 원문과 초안은 화면 메모리에 있으며 새로고침하면 사라진다. 사용자가 다운로드한 JSON은 평문이므로 회사 자료 보관 정책에 맞는 위치에 저장한다.
- API 요청은 `store: false`를 사용한다. 이것이 OpenAI 측의 모든 보관을 없애거나 무보관을 보장하는 것은 아니다. 회사 정책과 이용하는 API 계정의 데이터 처리 조건에 맞는 원문만 전송한다.
- 원문은 최대 12,000자, 요청은 동시 1건, 응답 대기는 최대 60초다. 실패 시 자동 재호출하지 않는다.
- 구조화된 응답과 인용 근거를 검사하지만 사실 정확성을 보장하지는 않는다. 수정한 값은 사용자 수정으로 표시하고, 원문 인용은 AI 추출 시점의 근거로 유지한다.
- 외부 폰트 로딩을 제거했다. SQLite 저장, Windows DPAPI/자격 증명 관리자 연동, 암호화 백업, Contract node 상세와 승인 후 노드 반영은 아직 구현하지 않았다.

`npm test`는 입력·근거 검증, 선박 주기 환산, OpenAI 요청 구성·실패 처리와 로컬 API 접근 제한을 검증한다. API 응답을 모의하여 실행하므로 실제 OpenAI 연결과 요약 품질 검증은 키 설정 후 별도로 필요하다.

## 서무 업무 노드와 공통 Due date

서무 업무는 항로 노드와 같은 업무 단위이며 통합 업무 보드에서 함께 배치한다. 데이터 구조와 상세 동작은 종류별로 구분한다. 고유 ID, 업무명, 고정 분류 `서무 업무(기타)`, 최근 업데이트일, 업데이트 주기, Due date, 업무 가이드라인과 자동화 마법사 진입점을 제공한다. 현재 화면의 업무는 예시이며 브라우저에 저장한다. 가이드라인 화면에서 최근 업데이트일·주기·가이드를 수정하면 Due date가 재계산된다.

Route node와 서무 업무 노드 모두 `Due date = recent update date + 업데이트 주기`를 적용한다. 화면에는 날짜와 `D-남은 일수`, `D-day`, `D+경과 일수`를 함께 표시한다. 월·분기·연간 주기는 달력 기준으로 계산하고 대상 월에 같은 일이 없으면 월말로 맞춘다. 선박 n척은 n주로 환산한다. 최근 업데이트일·주기가 없거나 유효하지 않으면 미정으로 표시하고, 종료된 Route node에는 다음 Due date를 부여하지 않는다. 예시 보드는 2026-10-13 기준으로 D-day를 계산한다.

서무 업무 자동화 마법사는 선택한 업무의 정보와 가이드라인을 편집 가능한 원문으로 준비한다. 이 단계에서는 외부 전송하지 않는다. 사용자가 원문을 확인하고 전송에 동의한 뒤 실행하면 업무 절차·자동화 제안·검토 체크리스트의 초안을 반환한다. 실제 파일 변경, 삭제, 메일 발송, 예약 실행은 수행하지 않는다. Due date는 GPT의 제안 날짜를 그대로 사용하지 않고 최근 업데이트일과 주기에서 계산한다. 현재 API 키가 없어 실제 GPT 호출과 제안 품질 검증은 미완료다.

## 통합 업무 노드 보드와 D-day 정렬

항로와 서무 업무는 한 보드에서 함께 표시하며 첫 화면은 전체 업무다. 종류는 카드의 항로·서무 배지로 구분한다. 전체·항로·서무 필터, 통합 검색, 권역·분류 및 업무·계약 유형 필터를 제공한다.

종류와 관계없이 Due date 오름차순으로 정렬한다. 오래 경과한 기한이 먼저 나오고, 당일, 가까운 미래 기한 순서로 이어진다. 기한 미정·유효하지 않은 기한·종료 노드는 마지막에 두며 동일 기한은 고유 ID 순서로 정렬한다. 문자열 D-day 표기를 정렬하지 않고 실제 날짜를 비교한다. 가이드라인 화면에서 최근 업데이트일이나 주기를 저장하면 기한과 카드 순서를 즉시 다시 계산하며 현재 필터는 유지한다. 기존 항로·서무의 브라우저 저장 데이터와 상세 기능은 유지한다.

## 항로별 업무 매뉴얼 페이지

업무 보드에서 항로 카드를 선택하고 **업무 매뉴얼 페이지 열기**를 누르면 해당 Route ID에 연결된 Notion 스타일의 블록 편집 페이지가 열린다. 실제 Notion 서비스와 연동하지 않고 앱 내부에서 실행된다. 커버, 아이콘, 페이지 제목, 항로 연결 정보와 수정 시각을 표시한다.

본문, 큰·작은 제목, 글머리·번호 목록, 체크리스트, 안내 상자, 인용, 구분선, 코드와 링크 블록을 추가·수정·삭제·이동할 수 있다. 빈 본문에서 `/`를 누르거나 블록 종류 메뉴를 열어 형식을 선택한다. Enter는 다음 블록을 만들고 Shift+Enter는 줄을 바꾼다. 읽기 모드, 명시적 저장, JSON 페이지 백업·불러오기를 제공한다. 백업은 현재 Route ID에 일치하는 문서만 초안으로 불러오며 저장 전에 검토할 수 있다.

매뉴얼은 항로 데이터와 별도의 브라우저 저장 키에 저장한다. 저장된 수정 시각과 저장 회차를 표시하며 이전 버전의 내용은 보관하지 않는다. 저장은 Route의 최근 업데이트일·History·Due date·보드 정렬을 변경하지 않는다. 저장하지 않은 초안은 현재 앱 세션 안에서 항로별로 유지되지만 새로고침하면 사라진다. 저장 오류 시 작성 내용을 유지하고 백업을 안내한다.

기존 Markdown 매뉴얼은 읽을 때 블록으로 변환한다. 이전 저장 키의 원문은 삭제하거나 덮어쓰지 않고 새 페이지를 저장할 때 새 키에 기록한다. Markdown 표는 탭으로 구분한 코드 블록으로 옮기며 일부 인라인 서식은 일반 텍스트로 변환한다. 원본 Markdown은 기존 키에 보존된다.

본문은 HTML로 실행하지 않고 텍스트로 렌더링한다. HTTP/HTTPS 링크만 사용자가 클릭해 열며 `noopener noreferrer`를 적용한다. 외부 이미지·스크립트를 로딩하거나 내용을 외부 AI로 자동 전송하지 않는다. 현재 저장은 암호화된 Windows 파일이 아니라 브라우저 저장이며, 내려받은 JSON 백업은 평문이다. 회사 자료 보관 정책에 맞는 위치에 보관한다.
