# 확정 요구사항

## 제품 범위

Worknote는 Windows 개인 PC에서 항로·서무 업무, 계약 참조, 업데이트 이력과 업무 매뉴얼을 관리하는 앱이다. 로컬 저장이 기본이며 GPT 정리만 사용자가 선택한 내용에 한해 외부 API를 사용한다. Gmail은 후속 과제로 미룬다. Notion과 비슷한 페이지 UI를 앱 내부에 제공하며 실제 Notion 계정을 연결하지 않는다.

## 업무 보드

Route node와 서무 업무 node는 동등한 업무 단위다. 같은 보드에 섞어서 표시하고 전체·항로·서무 필터, ID·업무명·항로명·파트너 검색을 제공한다. Contract node와 History node를 독립 업무 카드로 나열하지 않는다.

정렬은 실제 Due date 오름차순이다. 오래 경과한 기한, 당일, 가까운 미래 기한 순이며 미정·잘못된 날짜·종료 항로는 마지막이다. 동일한 기한은 ID 순서다. D-day 문자열 자체를 정렬하지 않는다.

## Route node

| 항목 | 정의 |
| --- | --- |
| ID | 고유 번호. 같은 항로명이라도 서로 다른 계약 관계는 별도 ID |
| Route name | 대문자 코드 목록과 한글 표시명. 여러 코드를 한글명으로 통합 가능. 교환은 두 코드를 `AAA-BBB`로 표시 |
| 권역·종류 | 인도, 베트남, 태국, 하이퐁, 아프리카, 미주, 일본, 중국, 중동 등. 상위 지리 그룹을 별도 관리하고 분류 명칭은 변경 가능 |
| Start date | 최초 계약 성립 시점. `YYYY-MM` |
| Terminate date | 만료·폐기·이탈·미갱신 시점과 사유. 상세 날짜 정밀도는 실제 입력 기준으로 후속 확정하며 초기 UI는 `YYYY-MM` |
| Partners | 별도 선사 테이블의 대문자 코드와 연결. 공동운항자·구매자·판매자·교환 파트너 역할 구분 |
| Contract type | `joint`, `sell`, `buy`, `exchange` |
| Recent update date | 내부 History의 가장 최근 업데이트 날짜 |
| 업데이트 주기 | 매월·분기별·연간·선박 n척 기준 n주 추정 |
| 최근 업데이트 항목 | 선복료, BSA, 선박변경, surcharge, Draft, rotation, max unit 및 사용자 항목 |
| Due date | 최근 업데이트일 + 주기. 날짜와 D-day를 함께 표시 |
| Remark | 기본 전제와 실무 비고 |
| 업무 매뉴얼 | 해당 ID에 연결된 블록 편집 페이지 |

교환은 다른 두 항로의 물량을 바꾸며 1:1로 가정하지 않는다. 교환 물량·비율·추가 구매 흡수 조건과 선복료 계산식 등 기밀 계약 상세는 앱에 보관하지 않고 연결된 Notebook에서 확인한다. 원 계약·추가 계약의 참조 연결은 ID로 관리한다.

## History node

Route 내부 테이블로 소유 항로 ID에 연결한다. 헤더는 `Update date`, `Cycle`, `업데이트 항목`, `Remark`다. 한 업데이트에 여러 항목이 있을 수 있다. Cycle은 계약별 적용 기간·회차를 표현하며 계약의 업데이트 주기와 별개다. 실제 변경 기록을 남기고 AI 요약과 구분한다.

## Contract node

계약 고유 ID, 최소 표시명, 관련 LLM notebook 링크, 연결된 Route ID 및 기밀을 제외한 비고를 관리한다. 기밀 원문, 첨부 계약서, 상세 조건을 저장하지 않는다. Notebook은 사용자가 링크를 열어 해당 서비스의 계정·권한으로 확인한다. 앱이나 GPT가 링크 내용을 자동으로 읽지 않는다. 다중 항로·계약 연결을 표현할 수 있도록 관계 테이블을 둔다.

## 서무 업무 node

고유 ID, 업무명, 고정 분류 `서무 업무(기타)`, 최근 업데이트일, 업데이트 주기, Due date, 가이드라인과 자동화 마법사를 제공한다. 실무적 성질은 항로와 다르지만 보드의 우선순위는 같은 기한 규칙으로 계산한다.

## 주기와 D-day

1주 1척을 기본 가정으로 계약의 n척을 n주로 환산한다. 실제 운항 종료를 판단한 값이 아니라 추정값이다. 월·분기·연간 계산은 달력 기준이며 대상 월에 같은 일이 없으면 월말로 맞춘다. 기준 정보가 없으면 기한을 만들어내지 않는다. 기한 경과는 확인 요청이며 자동으로 실제 운항 지연으로 단정하지 않는다.

기한 전은 `D-n`, 당일은 `D-day`, 경과 후는 `D+n`이다. 반복 실행은 최근 업데이트를 기록했을 때 다음 기한으로 바뀌며 경과했다고 자동으로 미래 회차로 밀지 않는다.

## 매뉴얼 페이지

커버, 아이콘, 제목, 항로 연결 정보와 매뉴얼 수정 시각을 제공한다. 본문·제목·목록·체크리스트·안내·인용·구분선·코드·링크 블록을 직접 편집한다. 원시 HTML은 실행하지 않는다. 매뉴얼 저장은 항로 업데이트일·History·기한을 변경하지 않는다. 기존 브라우저 매뉴얼을 이전할 때 원본을 보존한다.

## GPT 마법사

내용 요약, 항로·History 정형화, 서무 가이드 기반 자동화 절차 초안을 제공한다. 원문 확인과 외부 전송 동의 후 호출하고 원문 근거·누락·충돌을 표시한다. 결과는 사용자 검토·수정 후에만 적용한다. 초안이 실제 파일 변경·메일 발송·예약 실행을 수행하지 않는다. API 키는 서버에만 두고 실제 회사 자료를 테스트에 사용하지 않는다.

## 초기 완료 기준

로컬 DB 전환 후 앱 재시작에도 데이터가 유지되고, 노드 ID 연결·기한 정렬·History·매뉴얼 분리가 검증되어야 한다. 백업 후 복원 결과를 확인해야 한다. 현재 UI의 샘플·브라우저 저장과 API 모의 검증은 이 완료 기준을 대체하지 않는다.
