# 구현 순서와 검증 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 현재 | 통합 보드, Due date 계산, 서무 가이드, 블록 매뉴얼, GPT 호출 코드 | 예시 UI·계산·모의 API 테스트 통과. 실제 회사 사용 준비 완료를 의미하지 않음 |
| 1 | Windows 경로·SQLite 저장 서비스·migration runner | 빈 DB 초기화와 재실행이 안전하고 체크아웃 밖에 저장 |
| 2 | 노드·파트너·권역 CRUD, Contract Notebook 참조 | 같은 항로명의 다른 ID 보존, HTTPS 링크 검증, Notebook 자동 조회 없음 |
| 3 | History 저장·공통 보드 API 연결·브라우저 데이터 이전 | 최근 업데이트 기준 기한 계산, 중복·누락 없이 원본 보존, 재시작 후 유지 |
| 4 | 블록 매뉴얼 DB 저장·백업·복원 | 항로 업무 기록을 변경하지 않고 편집·복원, 잘못된 백업은 거절 |
| 5 | Windows 자격 증명 저장소·암호화 백업 | 키·원문 로그 노출 없음, 실제 복원과 접근 권한 확인 |
| 6 | GPT 실제 호출·초안 승인 적용 | 가상 원문으로 품질 확인, 무근거 값 미확인, 사용자 승인 없는 노드 변경 없음 |
| 7 | 주기별 확인 알림·로컬 패키징 | Windows 재시작 후 알림 상태 복구, 중복 방지, 설치·제거 시 개인 데이터 보존 |
| 후속 | Gmail 입력, 자동 요약·도메인 위키 | 별도 권한과 사용자 요구 확정 후 구현 |

실제 계약 상세의 앱 저장·Notebook 자동 수집·AI 제안의 무승인 실행은 구현 범위에 넣지 않는다. 로컬 구문·테스트 성공, Windows 실제 검증, GitHub CI 성공, 앱 패키징 완료는 각각 별도로 기록한다.
